窄而真实的 4 个资源合约

ResourceSnapshot

raw thermal、Low Power Mode、foreground、headroom、Metal bytes、active reservations、evidence age。绝不包含 runMode 或认知深度。

WorkloadDescriptor

model digest、shape、bytes、latency class、determinism、allowed equivalent backends。没有 user text、candidate 或 risk verdict。

SiliconLease

policyLeaseRef、backend/runtime、GPU/ANE exclusivity、bytes/concurrency cap、checkpoint/expiry、thermal exit rule。不可转让。

ExecutionReceipt

实际 backend、placement evidence 或 honest unknown、queue/prefill/decode ms、peak bytes、thermal delta、fallback reason；每个 counter 标 measured/estimated。

热状态：不牺牲质量，只改变机械路径

Nominal

单一 GPU owner；MTP 与 NAX 依 device profile；允许 model warm residency。ANE 只可作为独立替代 lane，不与 target 并跑。

Fair / Low Power

停止后台 accelerator、并发收至 1、关闭 speculative prefetch；MTP 必须过 matched never-worse profile，否则 plain。

Serious

强制 plain；禁止新 model load/JIT、GPU embedding 与 spill fan-out。保留完整 verifier/sovereign，不把 4B 转 CPU继续烧。

Critical

round boundary checkpoint；defer/cancel 非必要 turn，释放非关键模型，只允许 durable reconciliation 与 L14 finalize。宁可慢/等，不偷偷降质。

“满血”的严格定义

热控可以选择等候、缓存、复用、换成已通过等价性认证的 backend、关闭负收益 speculative；不能暗中换小模型、降精度、跳过验证或放宽 L14。40 tok/s cold / 30 tok/s hot 仍作为性能目标分开验收，但持续 100% duty 的 hot-30 不能靠调度承诺；若物理上达不到，系统应诚实排队或降速，而不是牺牲答案质量。

选择资源调度哲学

A · Phase-owned heterogeneous

每个 phase 一个重型 owner；CPU/GPU/ANE 交接而非抢跑。真实 profile + lease + receipt。最快、最冷、边界最清楚。

B · Parallel saturation

CPU/GPU/ANE 尽量同时工作。看起来“满血”，但 Air 真机已有 ρ=0.83 的反证，热与统一内存争用最大。

C · GPU monolith

所有 ML 都串在 GPU。简单，但 tiny heads、低功耗 reader、Secure Enclave 和背景维护无法各就其位。
