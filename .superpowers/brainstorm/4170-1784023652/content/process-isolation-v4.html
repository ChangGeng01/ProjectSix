v4 · Dual Mesh 上的选择性进程隔离

按信任区切进程，不按 L1–L14 平均切进程。语义层编号保持不变，transport 只是部署平面。

平台现实

当前工程最低 iOS 18；Enhanced Security helper extension / 自定义 ExtensionFoundation 进程按 iOS 26+ feature gate 使用。iOS 18–25 继续走同一组 ports 的 in-process 实现，但必须携带 IsolationAttestation，不能假装安全等级相同。

Transport-neutral Port

同一个 `SovereignPort` / `EffectPort` 可由 in-process 或 XPC 实现；LayerCore 完全不知道部署位置。

IsolationAttestation

每轮记录 inProcess、regularExtension、enhancedSecurity、unavailable。高风险 policy 可要求最低隔离级别。

Peer + Payload Binding

XPC peer identity、audience、operation、payload digest、policy/snapshot、turn/epoch 全部绑定；不能拿 A 的消息调用 B。

No silent fallback

需要 enhanced isolation 而 helper 不可用时，deny/remand；绝不偷偷降成 host executor 后仍声称强隔离。

三个部署等级

推荐

Tier 1 · Selective

iOS 26+ 将 L14 放 Enhanced Security helper；Effect Broker 对可隔离 adapter 使用独立 extension。L2/L8 留 host。安全收益最大、性能损失最小。

Tier 2 · Hardened State

在 Tier 1 上增加 L8 Sensitive StateVault extension；只有高敏 domain 远程查询 projection。隔离更强，但有 XPC、索引重建、jetsam/recovery 成本。

Tier 0 · Compatible

iOS 18–25 或扩展不可用：ports 保持不变但在进程内执行，attestation 明确标记弱隔离；高风险能力可按 policy 被禁用。

明确不做

不做 14 个进程

语义层不是部署单元；会产生 IPC 风暴、生命周期碎片与不可控故障传播。

不把 L2/MLX 移入 helper

模型、KV、JIT 和 Metal residency 是 Air 热路径；跨进程复制/重载会破坏吞吐与内存。

不共享 sovereign key

不能为了 app-group 便利让 host 与 helper 共用私钥；否则进程隔离失去核心意义。

采用哪个进程隔离等级？

我推荐 Tier 1；Tier 2 可作为高安全模式，而不是默认热路径。
