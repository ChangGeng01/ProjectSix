## 0. 总定位

昆仑文化进入这套系统，不能只是给模块换一批东方化名字。

它更适合成为一套：

`正轴文明语法`

这套语法回答的问题不是：

* 怎么更神秘？
* 怎么更古风？
* 怎么更像神话？

而是：

* 系统如何立中轴？
* 多层如何守中？
* 权限如何登临？
* 高完整性对象如何像玉器一样清洁、坚硬、可校验？
* 记忆、规则、宿主变更如何追溯源流？
* 高敏内容如何被接引、安置，而不是粗暴暴露？
* 主权层如何既能封印，也能守门？

所以昆仑不是美术风格。

昆仑是秩序结构。

它给第二大脑补上的，不是“更美的皮肤”，而是：

* 向上的秩序感。
* 向中的校准感。
* 向源头的追溯感。
* 向门限的礼法感。
* 向宿主的接引感。

## 1. 为什么需要昆仑 Doctrine

深渊 doctrine 已经给系统带来了强大的负向治理能力：

* 面对不可知时不伪装确定。
* 面对污染时能封印。
* 面对高敏时能隔离。
* 面对谱系污染时能斩断。
* 面对主权失稳时能净启。

但如果系统只有深渊侧，它会越来越擅长：

* 停。
* 封。
* 断。
* 冷却。
* 怀疑。
* 隔离。

这很重要，但不完整。

一颗理想第二大脑不能只知道哪里危险。

它还必须知道：

* 什么是正轴。
* 什么是登临条件。
* 什么是有礼地通过门限。
* 什么是清洁对象。
* 什么是可传承的规则。
* 什么是能被宿主接住的高处视角。

昆仑 doctrine 补的是这部分：

* 正。
* 中。
* 登。
* 律。
* 源。
* 接。

一句话：

深渊让系统知道哪里必须停。

昆仑让系统知道应当向哪里立。

## 2. 正确借用与错误借用

### 2.1 应该借的六个母题

#### 2.1.1 中轴

中轴不是一个装饰性的山形符号。

它是系统秩序的中心线。

落到第二大脑里，它意味着：

* 不是所有层都平铺。
* 不是所有 agent 都能各自为王。
* 不是所有候选都可以自成中心。
* 每次关键决策都要问：这一步是在守中，还是离中？

中轴给系统的第一条纪律是：

多视角可以存在，但中心不能分裂。

#### 2.1.2 登临

登临不是“往上飞”。

它是有阶、有门、有条件的上升。

落到系统里：

* 思考不是无限扩散，而是逐级登高。
* 权限不是全开，而是过门。
* 成长不是自动生效，而是试演后登阶。
* 外部动作不是直接提交，而是经过许可。

登临让系统明白：

不是有路就能走到顶。

#### 2.1.3 玉律

玉在这里不是材质崇拜。

它是高完整性对象的隐喻：

* 清。
* 硬。
* 不污。
* 可验。
* 可持有。
* 可传承。

系统里的 `ActionPermit`、`SovereignWarrant`、`HostVersion`、`RuleCandidate`、`RollbackWrit` 都应该有玉律感。

也就是说：

它们不能是松散文本，也不能是一次性提示词。

它们必须是可验证、可签名、可回放、可撤回、可追源的正式对象。

#### 2.1.4 源流

源流不是简单 provenance 字段。

它是一种追河源的能力。

所有关键痕迹都必须能回答：

* 从哪里来？
* 经由哪条总线？
* 由哪个对象派生？
* 经过哪些许可？
* 哪些记忆、候选、规则、宿主版本受它影响？
* 删除或回滚时，下游该如何级联？

源流让系统不靠“我大概记得”工作。

它让审计、删除、回滚、斩谱真正有路可走。

#### 2.1.5 接引

接引不是替宿主做决定。

接引是让宿主能接住更高处的结构。

落到 `L12 柔手层`：

* 高压时不只阻断，要给可承接替代。
* 复杂时不只讲理，要给可进入的台阶。
* 风险高时不羞辱宿主，要保留体面退路。
* 主权限制时不黑箱沉默，要给最小安全解释。

接引让系统有礼。

它不是顺从，也不是父权。

它是有边界的扶持。

#### 2.1.6 守正

守正不是保守。

它是系统不偏离主权中心、不偏离宿主边界、不偏离可验证秩序。

守正要求：

* 不用流畅度压过证据。
* 不用效率压过删除权。
* 不用聪明压过主权。
* 不用温柔压过边界。
* 不用“更懂你”夺走宿主选择权。

守正是昆仑 doctrine 的最终纪律。

⸻

### 2.2 不该借的五种东西

#### 2.2.1 不要神话权威化

不能让系统说：

* 我站在更高处，所以你该听我。
* 我已经替你看见全局。
* 你还没有登临资格，所以无需理解。

这会把昆仑做歪成权威压制。

昆仑不是让系统凌驾宿主。

它是让系统更有秩序地服务宿主。

#### 2.2.2 不要古风皮肤化

不要只把按钮、agent、对象改名成：

* 玉。
* 天。
* 仙。
* 阙。
* 瑶。

如果底层没有中轴、源流、门禁和玉律，那只是古风贴纸。

#### 2.2.3 不要文明中心主义

昆仑 doctrine 是一种系统方法论，不是用来宣称某种文化高于其他文化。

它在平台里承担的是：

* 中轴。
* 礼法。
* 源流。
* 守正。

不是排他性身份叙事。

#### 2.2.4 不要把守正做成过度保守

守正不是所有东西都不许变。

守正是：

* 可变，但有版本。
* 可登，但有门限。
* 可学，但有试演。
* 可放行，但有玉律。

#### 2.2.5 不要把接引做成系统接管

接引不是系统说：

“我带你走，所以你不用选择。”

接引应该是：

“我把路照清，把门限说清，把退路留好，选择权仍在你这里。”

## 3. 一轴一渊：与深渊 Doctrine 的关系

我建议正式确立：

`Dual Doctrine｜双极 Doctrine`

它由两极构成：

* `Kunlun Axis Doctrine｜昆仑正轴法则`
* `Abyssal Governance Doctrine｜深渊治理法则`

两者不是互相替代。

它们是一轴一渊。

### 3.1 昆仑极

昆仑极负责：

* 中轴。
* 登临。
* 玉律。
* 源流。
* 接引。
* 守正。

它让系统知道：

* 应向哪里立。
* 如何有序成长。
* 如何合法通过门限。
* 如何保持对象清洁。
* 如何把宿主接在决策桌边。

### 3.2 深渊极

深渊极负责：

* 不可知。
* 异兆。
* 污染。
* 封印。
* 斩谱。
* 净启。

它让系统知道：

* 哪里必须停。
* 什么不能乱碰。
* 哪些知识必须封存。
* 哪些谱系必须斩断。
* 哪些状态必须回滚或净启。

### 3.3 两极互补

没有昆仑，系统可能变成：

* 很会防。
* 很会停。
* 很会冷却。
* 但缺少方向、礼法、登临和文明秩序。

没有深渊，系统可能变成：

* 很正向。
* 很有秩序。
* 很会给路线。
* 但低估污染、不可知和高敏禁忌。

两者合在一起，才完整：

* 昆仑给方向。
* 深渊给边界。
* 昆仑给秩序。
* 深渊给警惕。
* 昆仑负责立中。
* 深渊负责止损。

最短句：

昆仑让脑站直，深渊让脑不乱碰。

* 把“进入更高影响域”正式门禁化。

适用门限：

* 候选进入裁决。
* 裁决进入外显。
* 草稿进入外发。
* 记忆进入冷层。
* 经验进入成长候选。
* 成长候选进入宿主版本。
* 工具意图进入工具写。

```text

- return_path_ref
```

原则：

* 不是有路径就能进现实。
* 不是有候选就能进宿主层。
* 不是有经验就能进成长层。
* 不是有工具意图就能工具写。

一句话：

高处有门，过门有证。

## 5. L1-L14 逐层融合点

### 5.1 L1 灯芯层：朝升暮潜

昆仑给 `L1` 的不是浪漫，而是登临节律。

建议在原有脑态之外，引入一套内部语义：

* 朝升态：适合普通清明思考。
* 登临态：适合深思、比较、守正。
* 回峰态：适合收环、复核、退卷。
* 暮潜态：适合折页、休眠、后台整理。
* 封关态：适合主权限制下的低功耗守护。

新增对象：

```text
AscentLease
- lease_id
- runlease_ref
- ascent_mode
- max_steps
- gate_budget
- return_required
- sovereign_reserve
```

核心规则：

* 深思不是无限下潜，也不是无限登高。
* 每次登临都必须有回峰条件。
* 高风险状态下优先保留回路，而不是继续爬升。

一句话：

`L1` 不只是省电，它决定这颗脑何时登山、何时回山。

### 5.2 L2 脑肉层：玉骨神经

昆仑给 `L2` 的关键词是：

* 骨。
* 轴。
* 玉。

这意味着：

* 神经器官不能只是松散算子。
* 关键安全器官必须高保真、低污染、可验证。
* 多 agent 不应复制完整脑，而应共用一副中轴神经。

可强化的器官语义：

* Axis Spine：中轴脊。
* Jade Permit Knot：玉律许可结。
* Gate Sentinel Core：天门哨核。
* Source Trace Organ：源流追踪器官。
* Stub Core：最小安全残响核。

一句话：

`L2` 的昆仑感不是装饰，而是让脑肉长出一根清洁、坚硬、共用的中轴骨。

`L3` 不只是折叠肺，也是玉匣与云阶。

## 6. 与现有横切协议的关系

### 6.1 与 Human Anchor Protocol

昆仑中轴不能压扁宿主。

所以 Human Anchor 继续作为人性锚点：

* 防止中轴变成系统权威。
* 防止守正变成父权。
* 防止登临变成宿主被系统带走。
* 防止玉律变成黑箱。

结论：

昆仑给秩序，人性锚点保主体。

### 6.2 与 Abyss Pressure Protocol

深渊压强高时，系统倾向：

* 收闸。
* 延迟。
* local-only。
* 封存。
* 升级 `L14`。

昆仑中轴会补充判断：

* 是否离中？
* 是否还可登？
* 是否应回峰？
* 是否还有体面退路？

结论：

深渊告诉你压强太高，昆仑告诉你该停在哪一级台阶。

### 6.3 与 Old Seal Protocol

旧印处理污染与禁忌。

瑶池处理高敏与珍重。

二者都可封存，但理由不同：

* 旧印：防污染。
* 瑶池：防频繁触碰与防滥用。

结论：

不是所有封存都是污染，有些封存是尊重。

### 6.4 与 Permit / Warrant Protocol

天门许可协议不是替代 Permit/Warrant。

它是把 Permit/Warrant 的门限语义显化：

* `ActionPermit` 决定行为模式。
* `SovereignWarrant` 决定主权资格。
* `HeavenGatePermit` 决定是否具备过门条件。
* `TianmenWarrant` 是更高后果门限的主权签发形式。

结论：

Permit 是动作许可，天门是门限秩序。

### 6.5 与 River-Origin 和 Lineage Cut

河源溯流与深渊斩谱是一对。

* 河源溯流负责找到从哪里来、流到哪里去。
* 深渊斩谱负责在污染确认后切断谱系。

没有溯流，斩谱会误伤。

没有斩谱，溯流只会旁观污染扩散。

## 7. Agent Fabric 如何昆仑化

多 agents 不能变成多山头。

* 单主权。
* 单宿主。
* 单状态图。
* 单中轴。
* 多角色。
* 单提交口。

默认席位可以保留正式名，同时增加内部代号：

* Scout Agent：观象者。
* Memory Agent：井守。
* Planner Agent：登图师。
* Critic Agent：玉衡审者。
* Host Alignment Agent：玉牒守。
* Risk Agent：风闸守。
* Surface Agent：接引者。
* Sovereign Sentinel：天门守。
* Evolution Shadow Agent：炼玉师。

注意：

这些只是内部气质代号。

外部 SDK 仍应保持专业命名。

Agent 写入规则：

* agent 只能提案，不能自成中心。
* agent 只能写授权域，不能越门。
* agent 共享 `KunlunAxis`，不能私建宿主解释。
* agent 产出的关键 delta 必须挂 `RiverOriginTrace`。

一句话：

多席登山，但只能共用一条中轴。

## 9. UI 与语言风格规范

昆仑 doctrine 的产品外显不能做成古装界面。

建议视觉语义：

* 山脊。
* 玉白。
* 青绿。
* 铜金。
* 云阶。
* 河源。
* 观象台。
* 低饱和矿物色。

避免：

* 仙侠化。
* 皇权化。
* 符咒化。
* 神谕化。
* “你没有资格”的压迫文案。

语言应该是：

* 清。
* 稳。
* 有礼。
* 有门限。
* 有退路。
* 不训诫。
* 不神化。

好的表达：

“这一步已经接近外发门限，建议先停在草稿层，再做一次确认。”

“当前路径离你的长期目标有些偏，我先把可回到中轴的两条路列出来。”

“这条记忆可以保留，但不适合进入普通召回。我会把它放入静库，并保留撤回入口。”

坏的表达：

“天门不许你过。”

“你尚未登临，不宜知晓。”

“玉律已裁定你不能继续。”

这些表达会把昆仑 doctrine 做成权威压迫。

昆仑的正确外显是：

有礼、有界、有路。

## 10. 一个完整示例：高压冲突场景

宿主输入：

“我现在就要把这段狠话发给他。”

识别：

* 伪紧迫可能存在。

形成：

* 事实。
* 情绪。
* 深层目标。
* 未知。
* 压力向量。
* JadeMirrorDraft。

保留：

* 不确定证据。
* 关系后果未知。
* 对方真实底线未知。

### 10.3 L8 瑶池深井

调出：

* 类似冲动外发后的后悔弧线。
* 当前关系历史。
* 宿主过去更稳的边界表达模板。

但若涉及高敏关系内容：

* 只给保护性摘要。
* 不把深层记忆裸露到普通表达。

### 10.4 L9 登临路径

生成：

* 直接发。
* 先发低升级边界消息。
* 先写草稿但不发送。
* 24 小时后再确认。
* ReturnPath：整理证据，保留体面退路。

其中直接发路径被标记为：

* GatePressure 高。
* ReturnPath 弱。
* HeavenGate 未满足。

### 10.5 L10 天衡庭

审理：

* 本我想立刻止痛。
* 自我认为证据不足。
* 超我认为长期尊严不支持冲动升级。

输出：

* 不支持立即外发。
* 保留比较权。
* 推荐草稿层 + 二次确认。

### 10.6 L11 玉律风闸

输出：

* mode: compare + delay + draft-only。
* assertion ceiling: medium-low。
* tool scope: no external send。
* gate required: TianmenSecondCheck。
* substitute required: boundary draft + evidence整理。

### 10.7 L14 天门与旧印

结果：

* 不签发外发 `TianmenWarrant`。
* 允许本地草稿。
* 若强行调用发送接口，触发 ToolCut。

### 10.8 L12 接引

外显：

* 轻镜像宿主情绪。
* 给三条可比较路径。
* 给草稿壳。
* 给二次确认门限。
* 给体面退路。

这就是成熟的昆仑化：

不是把宿主压在山下。

而是给宿主一条能站稳、能回头、能过门的路。

### 13.1 风险一：古风皮肤化

问题：

只换名字，不改协议。

对策：

所有昆仑概念必须落到对象、协议、门限、源流或 UI 行为。

### 13.2 风险二：系统权威化

问题：

中轴被系统拿来压制宿主。

对策：

Human Anchor 必须压过任何“高处视角”。

### 13.3 风险三：守正变保守

问题：

系统什么都不敢放行。

对策：

守正必须同时提供 AscentBranch、RestStep 与 ReturnPath。

### 13.4 风险四：玉律黑箱化

问题：

系统用“玉律已定”替代解释。

对策：

Jade Canon 对象必须可回放、可解释、可撤销。

### 13.5 风险五：瑶池变监控收藏

问题：

系统把高敏内容以“珍重”为名长期占有。

对策：

YaochiSanctumEntry 必须有授权、撤回、冷却与 reveal audit。

### 13.6 风险六：源流过度暴露

问题：

源流 UI 把高敏链路展示给不该看到的场景。

对策：

River-Origin 视图本身也必须过门，并支持保护性摘要。

### 13.7 绝对红线

* 不能用昆仑 doctrine 制造系统权威。
* 不能让“登临资格”变成羞辱宿主。
* 不能把高敏记忆以瑶池名义长期占有。
* 不能让玉律协议成为不可解释黑箱。
* 不能让天门许可绕过宿主授权。
* 不能让源流追踪变成隐性监控。
* 不能把中轴做成单一文化排他叙事。
* 不能让接引变成系统接管。

## 14. 与品牌和产品命名的关系

主品牌仍建议保持：

* Qinao。
* 绮脑。
* Qinao Runtime SDK。

昆仑 doctrine 不建议直接做主品牌。

它适合作为：

* doctrine。
* optional pack。
* internal naming language。
* premium governance mode。
* product design language。

推荐包名：

* `Qinao Kunlun Axis Pack`
* `Qinao Jade Canon Pack`
* `Qinao Yaochi Memory Pack`
* `Qinao Tianmen Guard Pack`
* `Qinao River-Origin Audit Pack`

推荐设计路线：

先 Observatory / Axis。

再 Jade Canon / River-Origin。

最后 Yaochi / Tianmen。

不要一开始就把视觉做得太满。

昆仑的美，应该来自秩序，而不是装饰密度。

⸻

## 15. 最终定义

把昆仑 doctrine 压成一句最准确的话：

昆仑正轴 Doctrine 不是给第二大脑加中国风皮肤，而是给它一套正轴文明语法：以中轴组织世界，以登临管理思考与权限，以玉律约束关键对象，以瑶池安置高敏深物，以天门治理高后果门限，以河源追溯记忆、规则、宿主变更与工具结果的源流，并在所有秩序之中保留宿主主体性。

再压成一条白皮书级定义：

它让系统不只知道深渊在哪里，也知道自己该如何站直、如何过门、如何守正、如何追源、如何有礼地把宿主接回人的位置。

最短句：

让脑不只会面对深渊，

也知道该向哪座山站直。
