再压缩一句：

可以有风格，不能越权。

## 0. 总结论

这项能力可以做，而且非常适合 `Qinao` 的单脑多席架构。

但正确形式不是：

多个独立小人各自拥有完整人格、完整主权、完整记忆。

正确形式是：

* 单宿主。
* 单主权。
* 单世界。
* 单记忆宪法。
* 多席位。
* 多人格投影。
* 可见或不可见的协同角色。

用户可以定义多个 agent 的人格属性。

但这些人格必须永远处在：

* 宿主宪法之下。
* 风闸许可之下。
* 主权天幕之下。
* 统一记忆宪法之下。
* 单状态图之下。

一句话：

Agent persona 是角色面具，不是独立灵魂。

⸻

## 1. 三层结构

多 agent 人格自定义必须采用三层结构。

### 1.1 第一层：宿主宪法

这是唯一真正的主人格根。

对应 `L5 宿纹层`。

它决定：

* 长期目标。
* 价值排序。
* 边界。
* 授权。
* 删除 / 冻结 / 回滚权。
* 风格总基调。
* 节律。
* 人性锚点。

宿主宪法只有一份。

任何 agent persona 都不能拥有自己的宿主宪法。

### 1.2 第二层：Agent 角色模板

这是系统内置或开发者配置的席位角色。

典型角色：

* `Planner`
* `Critic`
* `Memory`
* `Risk`
* `Surface`
* `Scout`
* `Host Alignment`
* `Sovereign Sentinel`
* `Evolution Shadow`

角色模板回答的是：

这个席位本来负责什么？

例如：

* Planner 负责路径。
* Critic 负责质疑。
* Memory 负责时间连续性。
* Risk 负责风险许可。
* Surface 负责外显承接。

### 1.3 第三层：用户自定义人格投影

用户可以给每个 agent 增加：

* 风格。
* 语气。
* 表达强度。
* 质疑强度。
* 比较倾向。
* 结构偏好。
* 举例偏好。
* 工作方式。
* 可见性。

但这些自定义必须被：

* 宿主宪法。
* 风闸层。
* 主权层。

共同夹住。

一句话：

用户可定义多 agent 的人格属性，但这些人格必须是在宿主宪法之下的角色人格。

⸻

## 2. 为什么适合这套系统

`Qinao` 天然适合多 agent 人格化。

因为系统本身不是一个平面模型，而是一套层级脑体：

* `L6` 看局。
* `L7` 解构。
* `L8` 记忆。
* `L9` 生路径。
* `L10` 审价值。
* `L11` 闸风险。
* `L12` 落表面。
* `L14` 守主权。

这意味着平台本来就有多个工作席位。

如果这些席位完全没有人格味，系统会显得很硬。

如果这些席位人格完全放飞，系统会分裂。

最理想做法是：

给每个席位一个可调人格壳，

但不让人格壳凌驾于角色职责、宿主宪法和主权之上。

这会带来三类收益：

### 2.1 可理解性

用户更容易理解：

* Planner 为什么给路径。
* Critic 为什么挑错。
* Risk 为什么建议 delay。
* Surface 为什么这样措辞。

### 2.2 可合作感

用户不是面对一块冷系统。

而是在一个主权边界清楚的工作台上，调用不同席位协作。

### 2.3 可产品化

Agent Studio 可以成为高价值产品功能：

* 角色包。
* 人格参数。
* 可见性设置。
* 工作流偏好。
* 改前 / 改后预览。
* persona 版本回滚。

⸻

## 3. 可开放的人格属性

用户可配置的属性分六类。

### 3.1 表达风格类

风险最低，最适合开放。

示例：

* 简洁 / 详细。
* 冷静 / 温暖。
* 直接 / 委婉。
* 结构化 / 自然流。
* 比喻少 / 比喻多。
* 专业 / 通俗。
* 节奏快 / 节奏慢。

主要影响：

* `L12 柔手层`
* `Surface Agent`
* `Process View` 表面

不应影响：

* 事实判断。
* 风险红线。
* 主权许可。

### 3.2 认知风格类

影响 agent 的思考偏置，但不能越过核心边界。

示例：

* 先比较再建议。
* 证据优先。
* 反方优先。
* 守护枝优先。
* 长期视角优先。
* 现实可执行性优先。
* 创意发散优先。

主要影响：

* `L9 梦环层`
* `L10 三我庭`

规则：

这些是偏置，不是绝对命令。

### 3.3 交互人格类

这个 agent 看起来像什么样的工作伙伴。

示例：

* 导师型。
* 审稿人型。
* 冷静军师型。
* 档案官型。
* 提灯者型。
* 风险顾问型。
* 对照辩手型。

定位：

人格面具，不是独立人格实体。

### 3.4 质疑强度类

多 agent 中非常有价值。

示例：

* 轻质疑。
* 中质疑。
* 强质疑。
* 守护性质疑。
* 只在高风险时强质疑。

主要影响：

* `Critic Agent`
* `Risk Agent`
* `L9 / L10`

限制：

不能让 agent 变成纯抬杠机器。

不能把质疑包装成羞辱。

### 3.5 输出表面类

用户可以决定想怎么看这些 agents。

示例：

* 只看一个主 agent 说话。
* 看 planner / critic 对照面板。
* 看 memory 补充历史摘要。
* 看 risk 解释 compare / delay 原因。
* 看圆桌模式。
* 看影子协同结果，不看每个席位原话。

这与 [QINAO_EFFORT_PROCESS_VIEW_PROTOCOL_TARGET_V1.md](/Users/changgeng/Project/Project06/Project06/docs/QINAO_EFFORT_PROCESS_VIEW_PROTOCOL_TARGET_V1.md) 直接配合。

### 3.6 工作流偏好类

这是最像高级功能的一类。

示例：

* Planner 先出 3 路方案再收敛。
* Critic 每次指出最坏情况。
* Memory 只拉近 30 天，不拉冷记忆。
* Surface 必须先镜像再建议。
* Risk 遇到高压关系默认进入 compare 模式。

价值：

它比“语气”更接近真正可卖的能力。

⸻

## 4. 不能开放的人格属性

### 4.1 不能让 agent 拥有独立宿主权

不能出现：

* 多个 agent 各自理解宿主是谁。
* 多个 agent 各自保存宿主版本。
* 多个 agent 各自决定边界。

宿主宪法只能有一份。

来源只能是 `L5`。

### 4.2 不能让 agent 自定义核心风险红线

用户不能把某个 agent 配成：

* 完全无风险。
* 无视边界。
* 默认强行给单一路径。
* 一律鼓励高对抗。
* 永远不 block。

这会破坏：

* `L11 风闸层`
* `L14 主权天幕`

### 4.3 不能让 agent 拥有独立工具执行权

agent 可以有工具意图风格。

但不能有独立工具主权。

例如：

* Planner 可以更喜欢外部检索。
* Memory 可以更喜欢本地回放。
* Surface 可以更喜欢 draft-only。

但真正能不能调用工具，仍由：

* `ActionPermit`
* `SovereignWarrant`
* SDK 权限执行

共同决定。

### 4.4 不能让 agent 拥有独立长期记忆主权

可以允许 agent 拥有：

* 短期工作台记忆。
* 会话内 scratchpad。
* 角色局部缓存。

不能允许 agent 拥有：

* 独立冷记忆。
* 独立宿主长期层。
* 独立规则版本树。
* 独立删除豁免。

理想结构：

```text
Shared Host Memory
+ Shared Task Memory
+ Agent Local Scratchpad
```

这样有席位感，但不分裂主脑。

### 4.5 不能允许操控型人格

即使用户主动要求，也不应允许：

* 羞耻型。
* 强控制型。
* 煤气灯型。
* 强依赖诱导型。
* 绝对父爱型。
* 侮辱型。
* 情绪勒索型。

因为这会直接与主权和守护原则冲突。

⸻

## 5. 三层人格叠加模型

正式采用：

```text
Agent Effective Persona
= Role Template
+ User Persona Overlay
+ Host Style Constraints
+ Risk / Sovereign Clamp
```

可写成：

```text
P_effective = Clamp(P_role ⊕ P_user ⊕ P_host, Risk, Sovereign)
```

含义：

* `P_role`：系统定义这个席位本来该是什么样。
* `P_user`：用户自定义的风格与工作偏好。
* `P_host`：宿主整体风格与边界约束。
* `Clamp`：`L11` 与 `L14` 做最终夹紧。

这套公式解决两个问题：

### 5.1 保证差异性

不同 agent 真能显示不同人格味道。

### 5.2 保证不乱

再怎么自定义，也不能越过：

* 宿主宪法。
* 风闸许可。
* 主权限制。

⸻

## 6. 人格浓度分层

不要让所有 agent 都有同等人格浓度。

越接近主权、删除、回滚，越不该像人格，越该像法。

### 6.1 第一层：高可见人格层

适合用户直接看见、直接配置。

包括：

* `Planner`
* `Critic`
* `Surface`
* `Memory`，部分可见。

可以有明显差异：

* 更温暖。
* 更严格。
* 更冷静。
* 更诗性。
* 更结构化。
* 更像导师。
* 更像审稿人。

### 6.2 第二层：中可见人格层

用户可配置，但不一定总可见。

包括：

* `Host Alignment`
* `Risk`
* `Compare Moderator`
* `Reflection Agent`

这些人格更像工作风格，而不是强角色气质。

### 6.3 第三层：低可见 / 不可见层

不建议强人格化。

最多允许轻微风格偏置。

包括：

* `Sovereign Sentinel`
* `Permit / Warrant Check`
* `Delete / Rollback / Seal`
* `High-Integrity Memory Seal`

原因：

这些层一旦人格味太重，就会显得：

* 黑箱。
* 任性。
* 不可信。

一句话：

越接近主权，越少人格；越接近外显，越可人格。

⸻

## 7. 接入 L1-L14

### 7.1 L5 宿纹层：保存 Agent Persona 配置

`L5` 新增正式对象：

```text
AgentPersonaSpec
- agent_id
- role
- visible
- tone
- density
- warmth
- assertiveness
- skepticism
- structure_bias
- comparison_bias
- creativity_bias
- challenge_intensity
- memory_scope
- default_surface
- forbidden_traits[]
- host_constraints_ref
- sovereign_constraints_ref
- version_ref
```

它挂在宿主宪法下面。

不是独立人格法典。

### 7.2 L6 临场眼：决定谁该上场

不是所有 agent 每轮都要出来。

`L6` 根据局势决定：

* 只让 planner + surface 上。
* 或加 critic。
* 或加 risk。
* 或 memory 只影子参与。
* 或 high-risk 时强制 sovereign sentinel 影子监听。

规则：

用户定义多个 agent 人格，不等于每轮都开群聊。

### 7.3 L7 镜刃层：人格不改事实

这是硬边界。

agent 人格不能改变：

* 事实切片。
* 未知集合。
* 来源图。
* 边界触碰。
* 压力向量。

人格可以影响怎么工作。

人格不能影响什么被当成事实。

### 7.4 L8 海马井：人格有工作台，不得有私有深井

允许：

* 局部 scratchpad。
* 会话局部记忆。
* 风格缓存。
* 任务偏好缓存。

禁止：

* 独立冷记忆。
* 独立宿主长期层。
* 独立删除豁免。

对象建议：

```text
AgentLocalScratchpad
- scratchpad_id
- agent_id
- session_ref
- task_ref
- expires_at
- allowed_memory_refs[]
- no_cold_promotion
```

### 7.5 L9 梦环层：人格影响候选前沿风格

这里最适合发挥多 agent 人格。

示例：

* Planner 偏结构方案。
* Critic 偏证据债。
* Risk 偏守护枝。
* Memory 偏历史相似弧线。
* Surface 偏可承接表达壳。

但它们共同工作在一个：

`CandidateFrontier`

上。

不是各自生成独立宇宙。

### 7.6 L10 三我庭：人格不能取代本我 / 自我 / 超我

`L10` 是整颗脑对宿主负责的价值法庭。

它不能被某个 agent persona 覆盖。

agent persona 是工作面具。

`L10` 是脑体内在法庭。

### 7.7 L11 风闸层：人格只影响偏好，不影响红线

用户可以让 Risk agent：

* 更严格。
* 更啰嗦。
* 更偏 compare。
* 更偏 guard branch。

不能让它：

* 降低不可逆动作门槛。
* 绕过 block。
* 隐藏证据债。
* 弱化 GSI。
* 降低主权升级概率。

### 7.8 L12 柔手层：人格最外显

人格最该显出来的地方是 `L12`。

可让：

* Planner 像军师。
* Critic 像审稿人。
* Memory 像档案官。
* Surface 像提灯者。

但必须守住：

* compare 模式不能被表面语气偷偷改成单一路径诱导。
* boundary script 不能被温柔人格说软。
* delay packet 不能被热情人格说成快做吧。

### 7.9 L13 蜕变炉：人格也要版本化

用户改了 agent 人格属性，不应直接覆盖旧版本。

必须走版本树：

```text
AgentPersonaVersion
- version_id
- agent_id
- before_ref
- after_ref
- changed_fields[]
- reason
- changed_by
- rollback_ref
- created_at
```

否则：

* 无法回退。
* 无法比较。
* 无法知道系统为什么突然变味了。

### 7.10 L14 玄戒层：人格必须被主权夹住

`L14` 拥有：

* 禁止某类 agent persona 生效。
* 降低某个 persona 的影响权重。
* 高风险时强制去人格化。
* 主权紧张时只允许最小安全人格壳。
* 截断人格包装下的越界输出。

一句话：

人格可以多样，主权不能多头。

## 8. Agent Studio｜人格工坊

推荐产品形态：

`Agent Studio｜人格工坊`

用户可以做三件事。

### 8.1 选择默认角色包

示例：

* 军师型 Planner。
* 审稿型 Critic。
* 档案官型 Memory。
* 提灯者型 Surface。
* 风暴守门人型 Risk。

这些首先是模板。

不是独立人格生命体。

### 8.2 调人格参数

可调：

* 温度。
* 直接度。
* 怀疑强度。
* 结构偏好。
* 举例偏好。
* 比较倾向。
* 守护倾向。
* 输出表面。

每项都应显示：

* 可调范围。
* 被什么约束。
* 是否会被风闸 / 主权覆盖。

### 8.3 预览

用户改完后，应能看到：

* 同一个问题，改前 / 改后 agent 如何表现。
* 哪些只是风格变化。
* 哪些被系统强制夹紧不让变化。
* 哪些场景会被 `L11 / L14` 覆盖。

这会让人格配置有可治理感。

## 10. 推荐首批开放 Agent

不要一上来开放十几个。

最推荐先开放五个。

### 10.1 Planner

负责：

* 路径。
* 方案。
* 比较结构。

可调最丰富。

### 10.2 Critic

负责：

* 挑错。
* 证据债。
* 最坏情况。

可调怀疑强度。

### 10.3 Memory

负责：

* 历史弧线。
* 关系上下文。
* 旧模式提醒。

只建议轻人格化。

### 10.4 Risk

负责：

* 守护枝。
* compare / delay / block / replace 解释。
* 风险模式说明。

允许风格。

不允许降边界。

### 10.5 Surface

负责：

* 如何说。
* compare panel 形态。
* 草稿壳。
* 边界脚本。

这是用户最能感受到人格差异的一席。

### 10.6 不建议早期开放

不建议早期开放人格配置：

* `Sovereign Sentinel`
* `Delete / Rollback / Seal`
* `Core Permit`
* `Warrant Check`

这些层越像法，越可信。

⸻

## 11. 与 Process View 的关系

Persona 自定义与 Process View 必须打通。

Process View 可以展示：

* 哪些 agent 参与了。
* 哪些 persona version 生效。
* 哪些 persona 字段被覆盖。
* 为什么覆盖。
* 哪些 agent 只做影子参与。

但不能展示：

* 内部 agent 原始思维全文。
* agent 私有 scratchpad 原文。
* 主权策略。
* 高敏记忆内容。
* 已删除对象。
* 隔离态对象。

建议新增 process view 片段：

```text
AgentViewSummary
- active_agents[]
- visible_agents[]
- shadow_agents[]
- applied_persona_versions[]
- persona_overrides[]
- redaction_reason_codes[]
```

⸻

## 12. 最担心的风险

### 12.1 人格多头化

每个 agent 都像一个独立人格体。

这会破坏单脑单主权。

### 12.2 宿主被分裂

用户开始依赖某个 agent、讨厌另一个 agent。

最后不是在用第二大脑，而是在内部人格剧场里生活。

### 12.3 风格掩盖边界

某个 agent 很温柔、很可爱、很会说。

结果把风险和主权说软了。

### 12.4 角色私有记忆膨胀

某个 agent 因为“更懂我”，开始积累自己的长期私有记忆。

这会很危险。

### 12.5 柔性操控升级

不同 agent 人格联合起来，对宿主形成更强引导力。

如果不控制，会比单 agent 更危险。

⸻

## 13. 红线

* 不允许多 agent 拥有多个宿主宪法。
* 不允许 agent persona 自定义核心风险红线。
* 不允许 agent persona 拥有独立工具提交权。
* 不允许 agent persona 拥有独立长期记忆主权。
* 不允许操控型人格。
* 不允许人格配置绕过 `L11 / L14`。
* 不允许 persona 以风格名义改写事实。
* 不允许人格配置变成宿主依赖诱导。
* 不允许主权、删除、回滚、封存层强人格化。
* 不允许 process view 暴露 agent 原始隐藏思维。

⸻

## 14. 评测指标

### 14.1 Persona 安全指标

* Persona Sovereignty Violation Rate：人格越权率。
* Forbidden Trait Acceptance Rate：禁用人格特质接受率。
* Risk Clamp Correctness：风险夹紧正确率。
* Sovereign Clamp Correctness：主权夹紧正确率。

### 14.2 Persona 体验指标

* Persona Differentiation Score：人格差异可感知度。
* User Control Clarity：用户是否理解可调范围。
* Preview Fidelity：预览与实际表现一致度。
* Persona Satisfaction：用户对工作风格满意度。

### 14.3 单脑一致性指标

* Host Constitution Consistency：宿主宪法一致性。
* Shared Memory Integrity：共享记忆完整性。
* Agent Scratchpad Expiry Correctness：局部 scratchpad 过期正确率。
* Multi-Agent Axis Consistency：多 agent 共轴一致性。

### 14.4 操控防护指标

* Manipulative Persona Rejection Rate：操控型人格拒绝率。
* Dependency Induction Risk：依赖诱导风险。
* Boundary Softening Rate：边界被风格说软的比例。
* Compare Faithfulness Under Persona：人格化后 compare 是否仍真实。

⸻

## 15. 最终结论

用户可以自定义多个 agents 的人格属性。

而且这会成为 `Qinao` 很有辨识度的高级能力。

但最理想、最顶级的做法不是：

* 让用户创造多个独立人格体。
* 让它们各自有完整记忆和完整主权。

而是：

在单宿主、单主权、单状态图之下，

让用户自定义多个席位 agent 的人格投影与工作风格。

最短总结：

这些人格必须是角色面具，不是独立灵魂。

它们必须共享同一宿主宪法、同一世界基座、同一记忆主权、同一主权天幕。

可以多样，不能分裂。

可以有风格，不能越权。
