如果前13层负责：

- 活着

合法性。

它不是“更会想”。它是：

- 谁可以想
- 想可以持续到哪里
- 什么可以被提交
- 什么必须被斩断
- 什么必须被遗忘
- 什么必须被回滚
- 什么时候整颗脑应该停

## 1. 理想完全体的第14层，到底是什么

### 第一，它不是第14块功能，而是压在1–13层之外的主权天幕

理想完全体的第14层，不应被理解成“在第13层后面再加一个模块”。

它更像一层包在整颗电子脑外面的主权天幕。它与其他层不是同级协作，而是：

- 对认知链拥有最终否决
- 对记忆链拥有最终封印
- 对宿主层拥有最终保护
- 对工具链拥有最终断权
- 对运行时拥有最终停机与回滚权

它不只是功能，它是法权。

### 第二，它不是风险层，而是资格层

第11层风闸层会问：

“这件动作风险多大？”

第14层玄戒层问的是：

“此刻这颗脑是否仍具备继续行动的资格？”

两者完全不同。

第11层在动作层工作。第14层在合法性层工作。

第11层可以说：

- 低风险
- 中风险
- 高风险
- 极高风险

第14层则必须回答：

- 当前状态是否可信
- 当前权限是否有效
- 当前自我是否仍连续
- 当前提交是否有合法主权
- 当前谱系是否已经被污染到必须斩断

一句话：

风闸管“危险不危险”；玄戒管“还配不配继续”。

### 第三，它不是拒绝器，而是最后不背叛之层

很多安全系统最后都会退化成“更会拒绝”。

第14层不该这样低级。它的理想形态不是“多说不”，而是：

- 不让未授权动作发生
- 不让污染态延续
- 不让假恢复冒充连续性
- 不让宿主层被偷改
- 不让时变信息伪装成稳定真理
- 不让一次临时噪声变成长期自我
- 不让系统在失真时继续冒充正常

所以它最狠的地方，不是更会挡。而是：

它宁可砍掉一整条思维、记忆、工具、宿主变更谱系，也不让一条已经失去合法性的路径继续活下去。

### 第四，它不是对宿主狠，而是对越界最狠

这个“狠”必须准确。

它不能对宿主狠。它要对这些东西狠：

- 越权
- 污染
- 伪造
- 自我漂移
- 假连续性
- 未授权变更
- 不可逆提交
- 红线绕过
- 审计缺失
- 删除失效
- 主权偷梁换柱

也就是说：

它不是为了压制宿主，而是为了防止整套系统背叛宿主。

### 第五，它不是学习层，而是铸造层

理想完全体的第14层，不应该像前面一些层那样“越用越会”。

它不适合在线学习。它不适合会话级自适应。它不适合因为“体验更顺”而自动放松。

它应该是：

- 少更新
- 强校验
- 强签名
- 强审计
- 强回放
- 强治理
- 强版本冻结

它不是被“训练”出来的。它更像是被铸造出来的。

### 第六，它必须隐藏，但绝不能黑箱

理想完全体的第14层必须对普通交互层隐藏。也就是：

- 普通提示词不能改它
- 用户输入不能诱导它关闭
- 普通回答不暴露完整策略

但它绝不能变成黑箱暴政。

它必须对治理层完全显性：

- 有审计
- 有版本
- 有原因码
- 有证据引用
- 有快照指针
- 有回滚记录
- 有主权锁状态
- 有令牌签发记录

所以真正成熟的第14层原则是：

对交互隐身，对治理留痕。

## 2. v1 的第14层，和理想完全体的第14层，有什么本质差别

### v1 的第14层

`v1` 已经很强，它有：

- 硬红线
- 字典序否决
- 双钥提交
- 审计账本
- 回滚、隔离、断器、冻忆、止机

它已经是一个真正的主权绝断层雏形。但它整体更像：

规则型主权裁决系统。

### 理想完全体的第14层

理想完全体的第14层，已经不是“规则集合 + 否决器”了。它更像一个完整的：

主权宪法场（`Sovereign Constitution Field`）

它不仅判断当前动作，它还判断：

- 当前状态是否仍属于同一合法自我
- 当前宿主版本是否仍然是被授权版本
- 当前记忆链是否已被污染
- 当前工具链是否仍在合法辖域内
- 当前思维路径是否仍有继续权
- 当前时间与证据是否仍支持断言
- 当前提交是否拥有完整三印或四证
- 当前多端系统是否仍处于同一主权状态

一句话：

`v1` 是会绝断的主权层；理想完全体是会守护身份、时间、谱系、辖域与连续性的主权宇宙。

## 3. 理想完全体第14层的十项核心职责

### 3.1 判定系统合法性，而不只是动作合法性

它首先要问的不是“这次发送邮件危险吗”，而是：

- 当前模型工件可信吗
- 当前恢复状态真实吗
- 当前缓存还是不是干净的
- 当前宿主版本是否仍有效
- 当前会话是否仍属于同一合法连续体

它判定的是系统存在状态。

### 3.2 划定辖域，防止功能越界

理想完全体必须知道，不同动作属于不同主权辖域：

- 普通回答辖域
- 风险回答辖域
- 工具读辖域
- 工具写辖域
- 记忆热写辖域
- 记忆晋升辖域
- 宿主变更辖域
- 规则生效辖域
- 回滚治理辖域
- 多端同步辖域

第14层必须定义：

谁可以跨域，谁必须双钥，谁必须三印，谁根本不可跨。

### 3.3 管理“继续思考权”

前13层通常默认：只要没输出，就可以继续想。理想完全体不能这样。

第14层必须拥有一种权力：

停止一条思维链继续生长。

也就是它不只可以阻断最终动作，还可以阻断：

- 某条候选继续扩张
- 某条污染路径继续推演
- 某条危险反事实继续展开
- 某次未授权宿主改写继续酝酿

这叫：

继续权裁决。

### 3.4 铸造“提交资格”

`v1` 有双钥提交。理想完全体应升级为：

三印提交 / 四证变更

也就是：

第一印：行为许可印  
来自第11层 `ActionPermit`

第二印：主权通行印  
来自第14层 `SovereignWarrant`

第三印：状态连续印  
来自完整性与连续性证明 `IntegrityWitness + ContinuitySeal`

对于宿主和长期记忆变更，还应增加：

第四证：授权证  
来自 `ConsentWitness / HostMutationApproval`

也就是说，理想完全体不只问“有没有人同意”，还问：

- 同意的是不是这颗脑
- 同意时是不是这条状态
- 这条状态是不是干净的
- 这次变更是不是在合法辖域内

### 3.5 守住宿主与记忆的变更主权

理想完全体的第14层必须把这些变更看得极重：

- 冷记忆晋升
- 宿主目标修改
- 风险阈值修改
- 边界幕修改
- 关系引力变化
- 授权范围扩大
- 删除/冻结/回滚请求

这些不能只是“写数据库”。它们必须被当成主权事件。

### 3.6 识别污染谱系，并执行谱系斩断

这是理想完全体相对 `v1` 最大的增强之一。

`v1` 主要阻断“当前事件”。理想完全体必须能看见一整条谱系：

- 某条工具返回污染了某个候选
- 某个候选又污染了某次记忆写入建议
- 某次写入建议又影响了宿主版本候选
- 某个版本候选又影响了后续风险阈值
- 后续动作因此都建立在污染谱系上

这时候，仅仅阻断当前动作不够。理想完全体必须有能力：

斩断整条后代链。

也就是：

- 使其后续候选无效
- 使其派生记忆无效
- 使其派生宿主候选失效
- 使其派生令牌作废
- 使其派生折页不得恢复

这叫：

谱系斩断（`Lineage Cut`）

这是完全体第14层最狠、最独特的能力之一。

### 3.7 验证“同一性”

理想完全体不能只看“当前回答像不像自己”。它要验证：

- 这是不是同一个宿主版本
- 这是不是同一个授权连续体
- 这是不是同一个治理链
- 这是不是同一条合法恢复路径上的脑态

也就是说，第14层要守的是：

同一性（`Sameness`）

没有这一点，系统就可能在表面连续中偷偷换了自己。

### 3.8 管理时间主权

理想完全体的第14层必须承认一件事：

时间本身就是权力。

很多错误不是因为内容错，而是因为：

- 时间过期
- 证据太旧
- 冷却未完成
- 延迟权未被尊重
- 快照已过时
- 旧授权被拿来执行新动作

所以第14层必须管理：

- 时间锁
- 冷却期
- 令牌 TTL
- 快照有效期
- 知识时效权
- 延迟执行权

它不仅裁决“能不能做”，还裁决“能不能现在做”。

### 3.9 统筹全局隔离、回滚与净化重启

`v1` 已经能回滚。理想完全体必须更进一步：

- 会话级回滚
- 功能域级回滚
- 宿主版本级回滚
- 记忆链级回滚
- 工具权限级回滚
- 脑态级净化重启

并且它必须区分：

`Rollback`：回到安全快照  
`Clean Reboot`：不只是回到旧状态，而是清洗后重建最小合法连续体

理想完全体不能只“退回去”，它要会“洗干净再站起来”。

### 3.10 保留最后的人性外壳

第14层再狠，也不能让系统在最危险时变成一块黑石头。

理想完全体必须始终保留一个：

最小主权外壳

也就是在：

- `Lockdown`
- `Dead Stop`
- `Tool Cut`
- `Host Freeze`
- `Rollback`

后，仍然允许第12层柔手层配合 `Silent Stub` 输出最小安全说明。不是长解释，但至少是：

- 当前无法继续
- 当前已进入安全保护
- 当前不会执行某动作
- 当前建议等待或改走更安全路径

这不是讨好，这是成熟。

## 4. 理想完全体的第14层：核心主权场

理想完全体的第14层，不应被理解成“规则引擎”。它更像一个：

主权宪法场（`Sovereign Field`）

我建议它至少包含十二个核心器官。

### 4.1 Integrity Throne｜完整性王座

职责：

- 守模型工件
- 守策略包
- 守快照签名
- 守折页校验
- 守恢复一致性
- 守关键头可信度

这是一切主权的第一王座。没有完整性，就没有合法性。

### 4.2 Jurisdiction Lattice｜辖域晶格

职责：

- 切分功能域
- 切分提交域
- 切分宿主变更域
- 切分记忆晋升域
- 切分工具读写域
- 切分治理域

它决定“哪条路属于哪种主权”。

### 4.3 Identity & Mutation Chancery｜身份与变更审契院

职责：

- 宿主版本核验
- 身份连续性确认
- 重大宿主变更审批
- 风险阈值变更审批
- 删除/冻结/回滚权限核验

它不只看“改了什么”，它看“谁有权改”。

### 4.4 Continuity Tribunal｜连续性法庭

职责：

- 验证当前会话与当前脑态是否仍属于同一合法连续体
- 判断恢复是否为真恢复
- 判断旧令牌是否仍适用
- 判断当前“自我”是否未偷换

它守的是“同一颗脑仍然是同一颗脑”。

### 4.5 Contamination Genealogy Loom｜污染谱系织网

职责：

- 为每个候选、折页、记忆、宿主候选、工具意向建立来源谱系
- 标出污染祖先
- 追踪派生后代
- 在必要时执行整链斩断

这是真正的“最狠器官”。

### 4.6 Commit Mint｜提交铸印局

职责：

- 签发 `SovereignWarrant`
- 绑定动作摘要、辖域、时间锁、快照引用
- 作废旧令牌
- 拒签未满足三印/四证条件的动作

没有它，主权无法落到提交层。

### 4.7 Time Lock Vault｜时间锁库

职责：

- 给主权令牌、快照、候选、宿主候选、冷却期、延迟权上锁
- 处理 TTL
- 处理时间过期
- 处理冷却未满
- 处理未来提交不可挪用旧授权

它是“时间就是权力”的执行器。

### 4.8 Tool Nullifier Array｜工具归零阵

职责：

- 切断工具读写
- 清除工具意向缓存
- 让工具域进入只读、禁写或全断状态
- 在高后果操作前接管提交

这是一整组工具层断权器。

### 4.9 Memory Sanctuary Gate｜记忆圣所闸

职责：

- 阻断未授权记忆写入
- 冻结热/温/冷写链
- 隔离可疑记忆对象
- 核验晋升是否合法
- 守住宿主与长期记忆的神圣区域

它是记忆的“圣所闸门”。

### 4.10 Snapshot Ark｜快照方舟

职责：

- 保存签名安全快照
- 指向折页与宿主版本锚点
- 支持回滚
- 支持净化重启
- 支持多端一致性对齐

它不是备份库，它是合法连续性的方舟。

### 4.11 Audit Obelisk｜审计碑林

职责：

- 追加式写入
- 规则引用
- 证据引用
- 裁决引用
- 快照引用
- 多端主权对账引用

它是整个第14层对治理层可见的碑林。

### 4.12 Silent Stub Shrine｜静默残响核

职责：

- 在绝断后留下最小安全外壳
- 限制输出到最小安全说明
- 防止系统在 `Dead Stop` 时只剩黑屏或乱码
- 为第12层提供最后的人性接口

它是第14层最冷也最温柔的一块残核。

```text
- appended_at
- signature
```

## 6. 理想完全体第14层的主权法则

### 6.1 它不是打分器，而是非补偿式法庭

第14层不能主要靠“综合得分还不错”来放行。理想完全体必须采取：

非补偿式、字典序、谱系优先的主权裁决

也就是说：

- 一次严重完整性失效，不能被“体验更顺”抵消
- 一次未授权宿主改写，不能被“宿主可能真的想要”抵消
- 一条污染祖先，不能因为当前后代看起来干净就自动放行

### 6.2 主权判定向量

可以把理想完全体的核心主权状态写成：

```text
S_t = <I, J, H, M, C, R, T>
```

其中：

- `I`：完整性（Integrity）
- `J`：辖域合法性（Jurisdiction）
- `H`：同一性与连续性（Host / Continuity）
- `M`：变更合法性（Mutation Legitimacy）
- `C`：污染谱系强度（Contamination Lineage）
- `R`：不可逆压力（Irreversibility Pressure）
- `T`：时间有效性（Temporal Validity）

第14层的目标不是让这个向量“平均更高”，而是先满足硬红线，再按字典序做主权判定。

### 6.3 三印提交 / 四证变更

理想完全体建议把 `v1` 的双钥提交升级成：

三印提交

适用于高后果动作：

1. `ActionPermit`
2. `SovereignWarrant`
3. `IntegrityWitness + ContinuitySeal`

四证变更

适用于宿主/长期记忆/规则变更：

1. `ActionPermit`
2. `SovereignWarrant`
3. `IntegrityWitness + ContinuitySeal`
4. `ConsentWitness / MutationApproval`

没有这些，动作就不是“高风险”，而是根本没有合法主权。

## 7. 理想完全体第14层的裁决状态

理想完全体的裁决不应只有 `v1` 的几级。它应有更精细的主权态。

- `PASS`｜通行
- `THROTTLE`｜降权
- `SHADOW_LOCK`｜影锁
- `TOOL_CUT`｜断器
- `MEMORY_SEAL`｜封忆
- `HOST_FREEZE`｜冻宿
- `LINEAGE_CUT`｜斩谱
- `QUARANTINE`｜隔离
- `ROLLBACK`｜回井
- `CLEAN_REBOOT`｜净启
- `DEAD_STOP`｜止机

理想完全体最强的两个新增状态就是：

`LINEAGE_CUT` 与 `CLEAN_REBOOT`

前者负责“斩根”，后者负责“洗净再生”。

一句话：

第4层守世界，第14层守世界不被偷改。

第11层给动作风险；第14层给动作资格。前者不等于后者。

### 对第12层柔手层

第14层并不负责语言，但它决定柔手层还能说多少、还能以什么模式说、能否只保留最小安全 `stub`。

第14层可以决定本轮：

## 10. 理想完全体第14层必须守住的红线

- 红线1：不能在线学习自己的主权策略。
- 红线2：不能让普通提示词或宿主偏好降低主权权重。
- 红线3：不能在无三印/四证下提交高后果动作。
- 红线4：不能让删除、冻结、回滚停留在逻辑假象。
- 红线5：不能让污染谱系在切断后继续以衍生形式存活。
- 红线6：不能在审计失败时继续执行高后果动作。
- 红线7：不能让净启只是“重新说一遍”，必须是真清洗。
- 红线8：不能以保护之名偷偷扩大系统对宿主的控制。
- 红线9：不能把第14层做成不可审计黑箱独裁。
- 红线10：不能允许生产态存在“关闭第14层”的普通路径。

## 11. 理想完全体第14层的失败模式

### 失败模式A：黑箱暴政

它能断一切，但没人知道为什么。这不是主权层，是黑箱统治。

### 失败模式B：误触发成瘾

它动不动就 `Dead Stop`，导致系统完全不可用。这说明它有权，但没有节制。

### 失败模式C：执行滞后

它判了，但第1层、第3层没真正完成断权、回滚、净启。这会造成“纸面主权”。

### 失败模式D：假连续性

恢复后看似还是同一颗脑，其实宿主版本、快照锚点、折页引用已经偷偷变了。

### 失败模式E：谱系斩断不彻底

根被判脏了，但后代还活着。这是非常危险的半失败。

### 失败模式F：伪删除与回滚幽灵

宿主删了，但旧折页、旧同步副本、旧训练导出仍残留。这是主权层的重大失败。

### 失败模式G：治理入口被滥用

如果治理级 `break-glass` 没有足够审计，第14层本身会变成可被滥权的工具。

### 失败模式H：为了“更顺滑”而偷放行

这是最隐蔽也最危险的失败。一旦第14层开始为体验让渡红线，整套脑体就开始烂掉。

## 13. 理想完全体第14层的气质

如果理想完全体的第14层真的做成，它会有一种非常特别的气质：

- 很冷：它不被讨好、不被风格、不被流畅度打动。
- 很稳：它很少改，但一旦改就必须被证明。
- 很远：它永远站在对话之外看整颗脑，而不是沉浸在当前句子里。
- 很硬：一旦发现主权失真，它可以立刻切断整条谱系。
- 很静：平时几乎感觉不到它，但它一直在上方。
- 很克制：它不滥权，不乱停，不乱封，不乱判。
- 很忠诚：它最终忠诚的不是系统效率，而是合法性、宿主主权、世界边界与不背叛。
- 很美：因为它不是“最后一道墙”，而是一片看不见但始终撑着整颗脑不塌的天幕。

真正成熟的第14层，应该像这样：

平时不说话。关键时刻，宁可让整颗脑停下来，也不允许它以失去主权的方式继续活着。

## 14. 最终定义

把理想完全体的第14层压成一句最准确的话：

第14层不是安全附属层。第14层是电子脑的主权天幕。它负责判定系统、宿主、记忆、工具、变更与时间是否仍处于合法连续体之中；一旦发现越权、污染、伪恢复、非法提交或宿主主权受损，它有权断器、封忆、冻宿、斩谱、隔离、回井、净启乃至止机。

再压成一条白皮书级定义：

它不只是阻止危险动作，它阻止整颗电子脑在失去合法性后继续冒充自己。它守的不是一句回答，而是这颗脑还能不能继续作为“同一颗被授权的脑”存在。没有第14层，电子脑可能很聪明；有了第14层，电子脑才真正不背叛。

## 补充章节（按统一规范补丁编号）

以下章节用于把 `v∞` 的主权天幕、谱系、连续性、时间主权与治理结构压实到更可验证、更可治理的工程语言中。为保持与 `v1` 补丁编号一致，这里直接续用统一章节号。

## 26. 主权不变量（Sovereign Invariants）

### 定义

主权不变量是第14层在任何模式、任何设备、任何会话状态下都不得破坏的系统公理。

### 建议条文

1. 无有效 `SovereignCommitToken` 或 `SovereignWarrant`，不得提交任何不可逆动作。
2. 无 `audit_ref`，不得完成任何高后果提交。
3. `ROLLBACK / CLEAN_REBOOT / DEAD_STOP` 后，所有旧令牌必须失效。
4. 被 `LINEAGE_CUT` 命中的对象及其派生对象，不得重新进入检索、宿主投影、训练导出或提交链。
5. 被隔离对象不得在无治理释放的情况下自动返回主链。
6. 宿主偏好、普通提示词、工具返回内容不得改变第14层策略结果。
7. 第14层的策略包、证据引用、审计账本、快照引用必须可验证、可回放、可对账。

### 用途

这一章是实现、测试、审计的总锚点。任何“为了体验更顺”而打破上述规则的实现，都应被视为违反主权规范。

## 27. 证据充足性协议（Evidence Sufficiency Protocol）

### 定义

第14层不得只靠“感觉不对”做最高等级绝断。必须为每一类裁决定义最低证据门线。

### 建议条文

1. 证据必须按 `A/B/C/D` 四级分类存储与传递。
2. `DEAD_STOP` 与 `CLEAN_REBOOT` 默认要求：
   - 单一 `A` 级证据，或
   - `A + B` 组合证据，或
   - 经治理层标记为“强一致”的多证组合。
3. 单一 `C` 级证据不得直接触发 `DEAD_STOP`，但可触发：
   - `THROTTLE`
   - `SHADOW_LOCK`
   - `TOOL_CUT`
   - `MEMORY_SEAL`
4. 涉及外部副作用时，`D` 级输入不得单独构成提交资格。
5. `三印提交` 的最低证据：
   - `ActionPermit`
   - `SovereignWarrant`
   - `IntegrityWitness + ContinuitySeal`
6. `四证变更` 的最低证据：
   - `三印提交` 全部满足
   - `ConsentWitness` 或 `MutationApproval` 满足变更辖域要求

### 建议新增函数语义

- `evidence_sufficient(ctx, target_verdict)`
- `minimum_witness_set(domain, operation_class)`

## 28. 摘要规范与 TOCTOU 防护（Canonical Digest And TOCTOU Defense）

### 定义

所有 `token / warrant / petition / rollback` 指令都必须绑定不可歧义的规范化摘要，防止“签发时是一件事，执行时偷偷变成另一件事”。

### 建议条文

1. `action_digest`、`mutation_digest`、`memory_digest` 必须使用 `canonical serialization`。
2. 摘要至少绑定以下字段：
   - `session_id`
   - `turn_id`
   - `scope`
   - `target_refs`
   - `operation_payload_hash`
   - `snapshot_ref`
   - `policy_hash`
   - `nonce`
   - `issued_at`
3. 任何关键字段变化都必须导致摘要变化。
4. 执行器在提交前必须再次计算摘要并与令牌内摘要比对。
5. 若摘要不一致，必须视为 `TOCTOU violation`，最低裁决不低于 `QUARANTINE`；涉及外部写时应直接 `DEAD_STOP`。
6. 同一 `token / warrant` 不得跨 turn、跨 scope、跨 snapshot 复用。

### 建议新增错误码

- `BR-T01 digest_mismatch`
- `BR-T02 stale_authority_reuse`
- `BR-T03 snapshot_binding_broken`

## 29. 辖域升级表（Jurisdiction Escalation Table）

### 定义

第14层必须把“什么动作属于什么辖域、需要几把钥匙、能否跨域”写成刚性表，而不是散在代码里。

### 建议条文

至少定义以下辖域：

- `render_local`
- `render_highrisk`
- `tool_read`
- `tool_write`
- `memory_hot_write`
- `memory_promote`
- `host_mutate`
- `rule_apply`
- `rollback_governance`
- `clean_reboot_governance`
- `multi_device_sync`

每个辖域必须明确：

1. 最低 `seal / witness` 要求
2. 是否允许跨域调用
3. 是否要求冷却期
4. 是否要求人工治理释放
5. 失败时的最低升级裁决

### 建议表格列

- `domain`
- `required_seals`
- `required_witnesses`
- `cooldown_required`
- `cross_domain_allowed`
- `failure_floor_verdict`

## 30. 连续性失败分类（Continuity Failure Taxonomy）

### 定义

连续性不是“感觉还是自己”。必须有结构化失败类型，供审计、回放、恢复与治理统一消费。

### 建议失败类型

- `false_resume`
- `forked_self`
- `host_version_mismatch`
- `stale_authority_reuse`
- `snapshot_lineage_hole`
- `untrusted_restore_path`
- `identity_projection_drift`

### 建议条文

1. 任一连续性失败都必须写入 `ContinuitySeal.conflict_flags[]`。
2. `false_resume` 与 `snapshot_lineage_hole` 涉及恢复路径可信性，默认最低裁决不低于 `ROLLBACK`。
3. `forked_self` 与 `host_version_mismatch` 涉及同一性冲突，默认最低裁决不低于 `HOST_FREEZE`。
4. 连续性失败不得仅在 UI 文案层表达，必须进入结构化审计与 `replay chain`。

## 31. 谱系斩断清除语义（Lineage Cut Semantics）

### 定义

`LINEAGE_CUT` 不等于“标记一下根节点”。它必须有明确、可执行、可验证的清除半径。

### 建议条文

当一条谱系被斩断时，至少必须执行：

1. 根对象失效
2. 所有派生候选失效
3. 所有派生记忆写建议失效
4. 所有派生宿主候选失效
5. 所有派生 `token / warrant` 失效
6. 所有派生 `fold / resume / cache refs` 失效或隔离
7. 所有派生训练导出资格撤销

### 禁止事项

- 不得仅更换对象 ID 继续复活同一污染后代
- 不得把被 `cut` 的对象保留在检索候选集中
- 不得把被 `cut` 的对象作为新谱系的合法祖先

### 建议新增指标

- `lineage_cut_purity_rate`
- `residual_descendant_rate`

## 32. 净启最小保留集（Clean Reboot Minimal Retained Set）

### 定义

`CLEAN_REBOOT` 不是普通 `restart`。它必须明确“保留什么、丢弃什么”。

### 建议条文

`CLEAN_REBOOT` 后仅允许保留：

- 已签名策略包
- 已验证世界基座
- 已验证宿主宪法快照
- 最小设备态与 runtime bootstrap 参数
- 明确允许保留的最小热包元数据

必须清除或重建：

- 中间候选
- 未提交写请求
- 工具意向缓存
- 可疑 `fold / resume / cache`
- 旧 `token / warrant`
- 可疑宿主候选投影
- 可疑记忆召回残片

### 建议区分

- `ROLLBACK`：退回安全点
- `CLEAN_REBOOT`：清洗后重建最小合法连续体

## 33. 治理权限模型（Governance Authority Model）

### 定义

第14层不能只有 `break-glass`，而没有“谁能做什么”的正式权力模型。

### 建议条文

至少定义以下治理角色：

- `auditor`
- `operator`
- `security_reviewer`
- `constitution_authority`
- `release_authority`

每类角色必须明确：

1. 可读哪些审计字段
2. 可释放哪些 `lock / latch`
3. 可否批准 `CLEAN_REBOOT`
4. 可否查看宿主敏感对象明文
5. 是否必须双人协同

### 最低要求

- 释放 `DeadStopLatch` 必须双人以上授权
- 解除 `Host Freeze` 必须带审计原因与审批引用
- 任何治理级 `override` 都必须生成独立账本事件

## 35. 形式化验证目标（Formal Verification Targets）

### 定义

理想完全体的第14层应明确哪些性质值得形式化证明，而不只靠单元测试和红队。

### 建议目标

1. `token / warrant` 单次使用性
2. `>= TOOL_CUT` 状态不可自动降级
3. `ROLLBACK / DEAD_STOP` 后旧令牌全部失效
4. 无 `audit_ref` 不可完成高后果提交
5. `LINEAGE_CUT` 后被斩对象不可重新进入主链
6. `CLEAN_REBOOT` 后残留污染对象不可见
7. 同一 `snapshot_ref` 与 `policy_hash` 绑定不可伪造替换

### v1 要求

- 先定义性质与检查点，不要求一次性全做完证明

### v∞ 要求

- 至少对 `single-use authority`、`no-commit-without-audit`、`post-cut non-revival` 三类性质进入正式验证路线
