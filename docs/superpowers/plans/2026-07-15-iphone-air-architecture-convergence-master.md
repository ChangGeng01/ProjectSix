**Goal:** Converge the substantial implementation already present in `BehavioralAISubstrate` onto the approved `14 Semantic LayerCores + 4 Physical Kernels + 4 bounded ControlRings + 7 orthogonal planes` architecture without duplicating mature components or overstating iPhone Air performance.

**Architecture:** Use an inventory-first, **owner-led strangler** migration. Extend the current semantic owner, place legacy writers behind read-only migration adapters, and move exactly one authority seam at a sealed epoch boundary; do not build a parallel clean-room owner and later attempt to merge truths. Preserve proven decode, replay, canonicalization, thermal, and sovereign primitives, but converge authoritative control durability into one K3 nucleus before enabling the physical fast path. A compatibility path may remain during migration, but a turn may never have two authoritative answers, state heads, signatures, operation roots, or external effects.

## 4. Plan Authoring Contract and Executable Order

### 4.1 Required Reuse Decision on Every Task

Before the first red test, each domain-plan task records this block with concrete paths and symbols:

```text
Reuse Decision: R | E | A | M
Repository owner evidence: <rg command + current owner paths/symbols>
Apple/public/upstream primitive evidence: <relevant primitive, or "not applicable" with reason>
Absent invariant: <one exact invariant, or "none" for R/A>
Authority and mutable-state owner: <one owner>
Storage and recovery owner: <one owner or "none">
Dependency direction: <caller -> owner; no reverse dependency>
Compatibility/retirement: <projection, freeze, migration, and removal gate>
Duplicate-authority test: <test that fails if two owners can decide, store, consume, retry, or release>
```

`R` calls the current owner. `E` modifies that owner or a same-owner extension. `A` translates exactly once at a real boundary and owns no policy/state. Only `M` may introduce a production authority.

### 4.2 Create Proof and Missing-Owner Allowlist

For an `M` production owner, the Reuse Decision must additionally prove all eight design requirements: (1) repository search and exact owner candidates; (2) Apple/public/upstream search; (3) the absent invariant; (4) why extension, composition, a generic low-entropy primitive, or an adapter cannot satisfy it; (5) one authority, mutable-state owner, storage owner, and recovery boundary; (6) dependency direction and single-truth argument; (7) compatibility projection plus freeze/migration/retirement; and (8) mutation, crash, replay, and duplicate-authority tests. Missing any item changes the decision to `E` or `A`.

The absent ring/seven-view identities are an `E` extension of the existing `BASMotherboardArchitecture.swift` taxonomy owner, not a new authority. New production `M` ownership is limited to the approved design allowlist:

- keyed Artifact Mesh identity/CAS/store receipt and ordinary child attestations;
- immutable multi-lane semantic snapshot/barrier and typed state-requirement planning;
- one canonical cross-lane snapshot join, global hard-eligibility/conflict/coverage gate, and deterministic State Market selection owner;
- complete StateABI; the canonical silicon execution binding itself extends the existing `BASExecutionPlan` owner (`E`);
- one cross-framework application process MemoryLedger/reservation/heavy-owner/active-completion authority;

## 5. Migration Rules

1. **Contract first:** introduce an immutable RuntimeCore/BASOrgan contract and cross-platform vectors.
2. **Governed persistence only:** every self-ID-free payload independently ordinary-put, used for Artifact identity, or reopened uses the Contracts-owned `BASGovernedArtifactPayloadCodec`, declares one visible schema version and public schema-first initializer, and has exactly one registry entry plus current/backward-when-real/future/cross-target fixtures. Raw payload `JSONEncoder`/`JSONDecoder`, caller-selected accepted-version sets, type-local authority decoders, and field access before version rejection are forbidden. A backward migration is declared only for a proven previously authoritative Artifact wire version; legacy diagnostic JSON is a private bounded membrane, never invented Artifact history. SQL rows use their one numbered owner migration instead of double-registering as Artifact payloads.
3. **Adapter second:** make the current implementation conform without changing production behavior.
4. **Shadow comparison:** record old/new decisions and digests; the new path cannot release, commit, or dispatch.
5. **Parity gate:** require semantic, byte/termination, crash, memory, and replay parity appropriate to the seam.
6. **Single cutover:** flip one authority flag; the old path becomes compatibility-only and cannot produce a second result.
7. **Retirement:** remove the old authority only after at least one release cohort and rollback drill; keep decoding/migration adapters for proven persisted records.
8. **Topology projection:** the semantic DAG is the v2 topology owner, but its nodes execute through the existing turn engine/stage executors; the old stage plan becomes a frozen compatibility projection and cannot schedule a hidden second answer.
9. **Disjoint recovery:** K3 owns prepare/stage/seal/activate while Zone C owns dispatch/ack/indeterminate/reconcile; neither state machine may mutate the other's state.
10. **Owner-led storage strangler:** select one existing EventLog abstraction and one physical writer, import the legacy atom/user-state/cursor/outbox facts under a sealed checkpoint, advance the restoration/schema epoch, then freeze old SQLite/Rust/actor writers. Never dual-write old and new stores as a migration strategy.
11. **Memory cutover:** QinaoMemory public calls become scoped adapters into K3 commands before its dictionary loses write authority. Raw content migrates to encrypted content-addressed artifacts; direct atom tables become replayable projections or read-only migration inputs. A deletion cutover invalidates old snapshots and remains incomplete until all owner receipts and rescan close.
12. **Operation normalization:** create one `TurnOperationRef` at Attempt admission and keep exactly one active operation head. K3 monotonically allocates typed Provider-egress/effect ordinals with exact purpose/causal inputs; stream/final remain ordinal zero. Every Provider branch is exactly-once and proposal-only until K3 designates one terminal-answer source; migration rejects legacy IDs that cannot prove the exact parent/branch.
13. **Provider relocation before actuation:** move concrete Provider products out of `QinaoRuntimeSDK`, make the package graph point Provider → contracts, and freeze any SDK-owned model default before a physical Provider path can become authoritative.
