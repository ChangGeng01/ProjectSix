## 2. MTP-LANDING CHECKLIST（每条 MUST-INHERIT + 抄哪里）

**Byte-safety（结构性正确）**
- [ ] Greedy-only gate: 复用 `BASDecodeLanePolicy.isGreedyByteSafe(temperature:)` — `Sources/BASOrgan/BASDecodeLane.swift:115-117`（已验证在位, 注释明言"defined ONCE, cannot drift"）。temp>0 → `.plain`, 永不 speculate。
- [ ] ADR-039 verify 循环: accept longest argmax-prefix, **always emit target's own argmax**, 换 source 只改 K 不改 byte。模式在 `BASPromptLookupDecoder.swift:110-123` / `BASSaguaroLoop.swift:103-117` — 抄 pattern, **绝不 fork 这三个 kernel**（red-line, `git diff` 必须为空）。
- [ ] Cache 红线: cache-trim bounds + RotatingKVCache fail-closed + `_productionEOSTokenIds` superset + stop-before-EOS 不动。MTP 的 snapshot-restore（MambaCache 引用保留 + `KVCacheSimple.trim(2)`, `BASQwen35MTPSpecDecoder.swift:13-16`）必须尊重这些 bounds。
- [ ] Batch-invariance 判定: Qwen3.5 是 GDN-hybrid — 若 2-token verify forward 与单 token 路径在 MLX 里 batch 非不变, strict byte-identity 结构性不可达 → 用 `BASSuffixLookupProbe.swift:68-83` 的 STRICT/LOSSLESS 双模式 gate（full-attention 默认 strict, 否则 lossless + `BAS_SL_GATE` 式 override）。Mac 64/64 identity 是好兆头, 但 device 必须重验。

**Planner / engagement 集成**
- [ ] 新 `BASDecodeStrategy` case（如 `.mtpSpec(k:)`）+ capabilities 位, 照 `BASDecodeStrategy.swift:39-82` 的 draft-model/saguaro candidate 模式; `_execute` 加 dispatch case（`MLXOrganAdapter+Executor.swift:29-83`）。
- [ ] Capabilities 上报: 在 `_decodeCapabilities()`（`MLXOrganAdapter+PromptLookup.swift:184-189`）加 `mtpHeadLoaded` — planner 保持 framework-free。
- [ ] Profiler 注册: 独立 sourceID（如 `"mtp-qwen35"`), 每 turn fold accepted/proposed/rounds 进 `BASAcceptanceProfiler`（`BASAcceptanceProfiler.swift:11-89`）。**必须 surface accept stats**（见 §4 陷阱 2）。
- [ ] ADR-014 opt-in: default OFF 起步, kill-switch = `decodePlannerAutoSelect` 同款布尔（`MLXOrganAdapter.swift:304-311, 938-941`）; 开关关掉时与 pre-capability byte-equal。cert 过了才谈 default-ON（greedy-spec 先例: `SPEC_DECODE_CERT_RESULTS.md:91-108`）。
- [ ] Fail-closed + never-silent: MTP head 加载失败 → 单模型 byte-identical, 原因落 `draftLoadFailureReason` 同款字段（`MLXOrganAdapter.swift:244-256`）。
- [ ] Memory admission: head 加载前过 budget check（`BASMLXMemoryBudget.swift:62-67, 125-150` 模式, 只是 +240MB 不是 dual-residency）; jetsam 线 3248-3376MB, 用 `task_vm_info` phys_footprint 量（`BASCoreAIDecodeProbe.swift:34-43`）。

**G3 测量纪律（device probe 必备）**
- [ ] 8-step warmup + steady-state 计时（`BASCoreAIDecodeProbe.swift:127-138`）; 两条 JIT 路径都要热（`BASSpecSpeedupProbe.swift:76-80`）。
- [ ] Thermal bracket: baseline-pre / MTP / baseline-post, ≥20s cooldown, shuffled order; 赢只算超出 drift band 的部分（`BASSpecDefaultOnProbe.swift:216-223`, `BASQuantABProbe.swift:107-114`）; log `ProcessInfo.thermalState`。
- [ ] 真 tokenizer count, 不是 chars/4（`BASSpecSpeedupProbe.swift:68-73`）。
- [ ] Validity guard: 无 error + 无 excluded turn + 两 arm 非空才算 VALID; INVALID 不出 PASS/FAIL（`BASSuffixLookupProbe.swift:182-205`）。
- [ ] Duration-weighted mean 防短 turn 噪声（`BASSuffixLookupProbe.swift:168-180`）。
- [ ] Memory honesty phase ordering: MTP-loaded lane 先跑（peak 是 process-lifetime, 无 reset）, baseline 后跑（`BASSpeculativeDecodeProbe.swift:28-31`）。
- [ ] ProbeFileLog + env-knob 配置（`BASProbeCommon.swift:24-70`）; verdict per-lane 永不 pool（`BASSpeculativeDecodeProbe.swift:1-9,199-204`）。

**Promotion gate（照抄 suffix-probe 结构, `BASSuffixLookupProbe.swift:186-199`）**
`gatePass = valid && speedup > 1.0(超 drift band) && free-form control ≥ 0.90× && acceptance > 0.05(silent-corruption 探测) && (strict ? byte-identity : ADR-039 lossless)` — 外加 G3 绝对线 ≥20 tok/s。

## 3. MTP 结掉/更新的未完事项

1. **Planner cold-start bug（`BASDecodePlanner.swift:50-57` 自认的 gap-audit finding）**: draft-model lane 在生产中 `_draftSpeculative` 不吐 accept stats → 永久 COLD → 2.7 floor INERT → free-form 会路由到 0.88× 亏损。MTP decoder 是自写 Swift 循环, **天然能 surface per-round stats** — 落地时把这个 plumbing 补上, 顺手把该 bug 的 MTP 侧关死（entropy-gate 是 draft-model 侧的临时药, 见下）。
2. **Qwen3.5 的 spec 空白**: decoder header 自述"production Qwen3.5 lane 今天 ZERO speculative"（vendored draft path 在 GDN 的 nonTrimmableCache 上 fail-closed; 1.46× 是 Llama-only）。MTP 直接填掉这个空 — Qwen 没有 same-tokenizer 小 sibling, 所以 draft-model lane 对 Qwen **永久不适用**, MTP 是唯一路径。文档里"Llama-only spec"的表述该更新。
3. **UDL Phase 2 suffix automaton**: 不被 MTP 取代（机制正交, model-free 零成本 vs MTP 每 iter 多一次 head forward）, 但优先级下降 — MTP 的 a≈0.88 是 **purpose-independent** 的（free-form 也接受）, 而 suffix 只赢 reuse-turn。留在 measurement-gate 后面即可。
4. **Fused decode kernel design（deferred）**: MTP 落地后 profile 前提变了（2-token verify forward 改变 dispatch 结构）; 若还要做 Step-1 profile, 在 MTP lane 上做。
5. **Verifier-lane default 之争**: MTP 让 `.greedy` 的论据更强（现在 greedy = spec + MTP 双赢面）; 但那个 probe 仍欠 COLD device 重跑, MTP cert 时可以顺路。

## 4. 现设计正走向的陷阱（过去经验点名警告）

1. **★最大陷阱 — floor 类别错配**: `minDraftModelAccepted = 2.7` 是按 1B-draft 的高成本 f 校的。MTP K=1 时 accepted-per-round ∈ [0,1], **a=0.88 永远过不了 2.7** — 如果 MTP lane 复用 draft-model 的 floor, 它会被 planner 永久 gate 掉（或者反过来, 复用 model-free 的 0.05 floor 则语义对但名字骗人）。MTP 的 f≈0.015（同权重一次读两 token）成本接近 model-free — 必须给它**自己的 break-even floor**（≈0.1-0.2 量级, 由 (1+a)/(1+f+(1−a))>1 解出 a>f≈0.015, 留 margin), 新参数, 不借旧的。
2. **Accept-stats 永久 COLD bug 的复刻**: 上一个 lane 就是因为 vendored `MLXLMCommon.generate()` 不吐 stats 才留下 `BASDecodePlanner.swift:50-57` 的洞。MTP 自写循环没借口 — 第一版就 fold telemetry。
3. **Entropy gate 可能反伤 MTP**: `maxDraftModelEntropyBits=3.0` 是为"free-form 时 draft 亏"设计的; 但 MTP 在 free-form 也 a≈0.88 且成本近零 — 若无脑套 entropy gate 会把 MTP 从它**最赚**的场景里踢出去。MTP lane 该默认**不受** entropy gate 管（或阈值另调）, 用 device 数据（free-form control ≥0.90×）证明后关掉。
4. **Mac→device 外推**: 84→120.6 是 Mac GPU bench。A19 上带宽比 Mac 低一个量级、且 ±44-78% 热漂移。1.44× 只是假设, G3 判决只认 device 上 bracket-mean 超 drift band 的 paired delta。绝对 tok/s 跨 session 不可比。
5. **Memory 侧较松但非零**: +240MB fp16 head 不是 1B draft, 但 4-bit 4B ≈2.2-2.4GB 权重 + head + KV + MLX runtime, 离 3248MB jetsam 线不远。admission check + phys_footprint 计量照做; 另外 fp16 head **不要顺手 quant**（v12 教训的类比: adapter/head 类小张量 sub-8-bit 会烂; 好在 ADR-039 下 head 变差只降 a 不改 byte — 但 a 降 = G3 挂）。
6. **Greedy-identity 的验收不能只看 byte**: byte-identical-but-broken source 照样 identical 而 acceptance 塌到 ~0（`BASSuffixLookupProbe.swift:193-197`）。probe 必须同时报 a; a 从 0.88 掉到 0.3 就是 head fold/norm 接错了, 即便 token 流全对。
7. **snapshot-restore 的隐性假设**: "MLX arrays immutable ⇒ snapshot free" 只在 vendored GDN kernel 不做 in-place cache 写的前提下成立。设计声称零 vendored 改动 — 加一个 debug assert（restore 后 re-decode 单 token == plain 路径同 token）进 device probe, 不要只信 Mac。

## 5. Bottom line: ≥20 tok/s 能不能到？

**物理上能到, 且大概率不靠 MTP 也擦线; MTP 提供的是热漂移下的安全余量。**

- 带宽账: A19 实测 ~50 GB/s; 4-bit 4B ≈2.2-2.4 GB/step → plain AR 上限 ~20-22 tok/s。参照系: 4-bit Llama-3.2-3B 实测 38 tok/s → 线性缩到 4B ≈28; Qwen3.5 是 ¾ GDN 线性注意力（decode 侧比 full-attention 便宜）, 冷机 plain baseline 合理预期 **~20-26 tok/s**。
- MTP 是**正确类型**的 lever: 过去一年杀死的方案（ANE draft ρ=0.86、kernel ~1.0×、sub-4-bit 质量塌、1B-draft 0.88×）全是撞带宽墙或成本墙; MTP 一次权重读出 1.88 个 token 的期望产出 = 直接摊薄带宽, 与 [[litert-onphone-reality]] 的结论("universal speedup = bandwidth reduction")完全同构。1.44× 打在 ~22 上 = **~30 tok/s 冷机**。
- 真正的敌人是 **热**: 本机 +44-78% drift 足以把 30 拖到 17。G3 必须定义为冷机、bracket-mean、20s-cooldown 协议下的数字, 否则 pass/fail 只是量热计。
- 第二敌人是 **memory**: 2.3GB + 240MB + KV vs 3248MB jetsam — 可行但要 admission gate 实测 phys_footprint, 别赌。
- 判决模板现成: 照 §2 的 promotion gate（speedup 超 drift band + control ≥0.90× + a>floor + identity/lossless）跑一个 `BASQwen35MTP` device probe, PASS 即关 G3。
